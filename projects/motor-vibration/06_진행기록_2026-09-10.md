## 구조 수정

Raw·Health·Telemetry payload를 하나로 합치는 것이 아니라, 하나의 Network Task가 API별 요청을 순차 관리하도록 로컬 수정함.

```text
센서 수집 → Raw/Telemetry 저장
             ↓
       단일 Network Task
       ├─ Raw batch
       ├─ Health
       ├─ Telemetry replay
       └─ 신규 Telemetry
```

- Raw 우선 처리.
- Raw queue가 비면 Health와 Telemetry를 처리.
- Replay/fresh Telemetry용 persistent client 재사용 방향 적용.
- Replay 실패 시 bounded backoff 적용.
- LittleFS watermark와 ACK 후 제거 순서는 유지.
- `accepted`가 실제 boolean `true`인지 Raw ACK에서 검증하도록 보강.

## 실장비 검증

### 성공

- N8 PlatformIO 빌드 성공.
- COM7 업로드 성공.
- PSRAM 인식 및 메모리 여유 정상.
- ADXL345 샘플 512개와 `quality=valid` 지속 확인.
- 일부 Raw HTTP `202`, Health HTTP `200` 확인.
- LittleFS assertion·Guru Meditation·메모리 부족은 관찰되지 않음.

### 재현된 문제

- Raw 요청이 약 4~6초 소요 후 HTTP `-1` 또는 `-11`로 실패.
- `start_ssl_client: -1` 반복.
- Telemetry replay가 `network-reserved`로 반복 보류.
- `pending=8`, `raw_queue=8` 포화.
- `WINDOW dropped` 및 `audio overwritten` 증가.
- LittleFS 큐를 0으로 초기화한 뒤에도 약 4분 관찰 중 큐가 약 68까지 증가.

### 해석

```text
센서 수집은 정상
→ 동기식 HTTPS POST가 수 초 점유
→ Network Task가 다음 전송을 처리하지 못함
→ Raw/Telemetry 큐 포화
→ Raw 구간과 음향 동기화 데이터 누락
```

따라서 단일 Network Task만으로는 HTTPS 지연 자체를 제거하지 못합니다.

## 서버 transmission 계약

기존 `windows` 객체는 유지하고 요청 최상위에 선택적 `transmission`을 추가합니다.

```json
{
  "windows": [],
  "transmission": {
    "policyId": "edge-trigger-batch-v1",
    "mode": "periodic",
    "reason": "none",
    "baselineId": "unconfigured",
    "droppedWindows": 0
  }
}
```

- `mode`: `periodic`, `priority`, `replay`.
- `reason`: 정상·진동 이탈·품질·저장 압박·복구 사유.
- HTTP `202`: 신규 저장.
- HTTP `200`: 동일 원본 중복 ACK.
- ACK는 저장 확인이며 RF66 분석 성공을 의미하지 않음.
- 정기·재전송 과거 데이터는 분석 이력으로 남고 현재 이벤트 상태와 분리됨.
- 360초는 정기 입력의 예상 최대 측정 나이이며, 우선/실제 이벤트의 기존 30초 기준은 유지.

## MQTT 검토

현재 제공된 명세에는 MQTT 통신 정의가 없습니다. 현재 변경은 HTTP API 확장입니다.

MQTT로 전환하려면 별도 결정이 필요합니다.

- Broker 주소·포트·TLS 인증서·인증 방식.
- topic 규칙: raw, telemetry, health, application ACK.
- QoS 및 재연결·오프라인 큐 정책.
- MQTT `PUBACK`과 Backend 저장 ACK의 구분.
- 기존 RF66 분석 파이프라인에 Subscriber 연결.

MQTT는 연결을 유지하여 메시지마다 HTTP/TLS 연결을 준비하는 비용을 줄일 수 있지만, 핫스팟 단절이나 처리량 부족으로 인한 큐 누적 자체를 자동 해결하지는 않습니다.
