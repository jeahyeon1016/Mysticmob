## 13-02 현재 구조와 오류 전파 경로 확정

- [x] `setup`, `loop`, FreeRTOS task, queue, mutex, LittleFS, HTTPS 호출 지도를 최신 코드 기준으로 작성
- [x] `continuous_vibration_runtime.h`의 전역 상태와 호출자 목록 작성
- [x] 실제 5분 로그의 `storage > 1280 ms`, `priority_scan_begin` 정체, actual drop 419를 코드 위치에 연결
- [x] 외부 계약과 내부 구현을 구분한 보존 경계 표 작성

확정한 오류 전파 경로:

1. `WindowFeatures`가 `writeRawSpool()`에서 느린 LittleFS 파일 생명주기를 기다린다.
2. `WindowHTTPS`의 `loadRawSpoolBatch()`는 최대 4개를 선택하기 위해 512 slot을 반복 스캔한다.
3. `serviceNetworkAuxiliary()`도 각 보조 API 사이에서 `priorityRawPending()`을 호출해 512 slot을 반복 확인한다.
4. selector가 HTTP에 도달하지 못하면 ACK와 spool 삭제도 실행되지 않아 저장 공간이 회수되지 않는다.
5. `pending=8`, `rawQueue=8`이 차례로 포화되고 `finish()`의 non-blocking enqueue가 실패해 `actual_drop_total`이 증가한다.

보존 경계:

| 경계 | 유지할 계약 |
|---|---|
| 캡처 | 800 Hz, 512 sample, non-blocking queue, index gap 보존 |
| 처리 | 특징 추출, 진동·음향 품질 독립, adaptive mode/reason 동결 |
| 저장 | temp write, flush/close, atomic rename, CRC read-back, ACK 전 보존 |
| 선택 | priority 우선, periodic 5분 cutoff, 최대 4개, index 오름차순 |
| 전송 | 동일 payload 재시도, HTTP 200/202 strict ACK, ACK 후에만 삭제 |
| 외부 계약 | 기존 JSON 필드, URL, 인증, 상태 분류, timestamp 형식 |
