# 작업 원칙

MythicMobs / BetterModel / Fabled 작업을 최소 컨텍스트와 출력으로 안정적으로 수행한다.

- 요청 범위만 수정한다. 불필요한 구현, 파일 추가, 추상화, 기존 구조 리팩터링을 피한다.
- 기존 코드와 설정을 현황의 기준으로 삼되, 명시적 요구사항을 우선한다. 불확실한 정보를 프로젝트 규칙으로 기록하지 않는다.
- 작업에 필요한 파일·구간과 직접 참조만 읽는다. 전체 문서·저장소·로그를 선제적으로 읽지 않는다. `병렬작업_인계.md`는 관련 작업에서 필요한 절만 참고하며, 과거 사양보다 현재 파일과 최신 요청을 우선한다.
- 외부 문서가 필요하면 `개발_참고사이트.md`에서 관련 자료만 선택한다. Main은 명세에 URL·필요 항목·적용 버전을 연결하고, worker는 필요한 부분만 확인한다. 단순 수정마다 모든 사이트를 다시 읽지 않는다.
- 버그 원인이 불명확할 때만 investigate-first로 먼저 조사한다. 원인이 명확하면 필요한 흐름을 확인하고 직접 수정한다.
- 단순 수정은 main agent가 묶어서 처리한다. 조사·수정·검토를 매번 별도 에이전트로 나누지 않는다.
- Caveman은 출력 압축에, Ponytail은 불필요한 구현 억제에 사용한다. 복잡한 신규 설계의 필수 구조나 정확성을 압축 때문에 생략하지 않는다.
- 검증은 변경 위험도에 맞는 최소 범위로 수행한다. 일반 작업은 변경 파일·구간만 확인하고, 전체 git diff는 대규모 또는 위험한 변경에서만 확인한다.
- 검증으로 요구사항 충족을 확인하면 추가 개선 없이 종료한다.

## 에이전트·병렬 작업

- 몹 기획·여러 단계 구현은 `tasks/README.md` 절차를 따른다. Main이 대상 명세 하나를 작성·갱신하고, 중요한 미확정 사항만 사용자에게 묻는다. 단순 수정은 명세를 불필요하게 만들지 않는다.
- 구현 worker는 새 문맥으로 생성하고(`fork_turns="none"`), 루트 지침·명세 경로·명세 리비전·담당 범위만 전달한다. 전체 채팅은 복제하지 않는다. 단일 몹도 구현 분량이 충분하면 위임하고, 독립된 작업만 병렬화한다.
- Main만 명세·공용 계약·통합을 관리한다. 파일마다 수정 담당자는 하나이며, 담당 밖 변경은 요청으로 전달한다. 역할별 상시 에이전트와 중복 조사·검증을 만들지 않는다.
- Worker는 지정된 `model/지역/몹 이름/` 원본만 수정한다. Git 변경·서버 반영은 main만 요청 범위 안에서 수행한다. 기존 ID는 요청 없이 바꾸지 않는다.
- 완료된 작업은 명세의 현재 상태로 인계한다. 새 Codex 작업은 사용자 요청 시 생성하며, main 채팅의 문맥이 자동 초기화된다고 가정하지 않는다. 토큰 절감률은 측정 없이 주장하지 않는다.

## 최소 검증

- 변경한 설정의 문법·직접 참조·상태 잠금·지연 합계 중 관련 항목만 확인하고, 기존 검사 도구가 적합하면 재사용한다. YAML 검사 통과를 플러그인·인게임 검증 완료로 보고하지 않는다.
- 서버 반영 시 원본과 사본의 일치 및 리로드 이후 오류만 확인한다. 몹 옵션은 새 테스트 개체로 확인하고, 모델 변경이 없으면 모델 재빌드를 생략한다. 전체 몹 삭제를 검증에 포함하지 않는다.

## 완료 보고

성공 시 기본 형식:

```text
done

- 변경 파일·핵심 변경
- 검증 결과(동작 변경의 인게임 미확인은 명시)
```

문제, 위험, 사용자 판단이 필요한 경우에만 설명을 추가한다. 사용자가 내용 공개나 상세 설명을 요청하면 그 요청을 따른다.
